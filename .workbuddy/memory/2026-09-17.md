## 「人机挑战 AI 不落子」根因排查（两个独立缺陷）
### 1. 本地服务缺 `.mjs` MIME（环境层）
- `vendor/onnxruntime-web/ort.wasm.min.js` 用**动态 `import()`** 加载 `ort-wasm-simd-threaded.mjs`；浏览器要求该响应为 JS MIME。
- `server.cjs` 的 `MIME_TYPES` 缺 `.mjs` → 返回 `application/octet-stream` → 动态导入失败 → ONNX 后端不可用 → `ZERO_THINK` reject → `ai_pice` 静默挂起，表现为“AI 不落子”。
- 实测报错原文：`no available backend found. ERR: [wasm] TypeError: Failed to fetch dynamically imported module: .../ort-wasm-simd-threaded.mjs`。
- 修复：`server.cjs` 增加 `.mjs → text/javascript`（并补 `.onnx`）；`tmp/server-check.cjs` 同步。
- `dev_server.py` 本来就有 `.mjs` 映射，所以用 9002 端口时一切正常——这也是“换个服务就正常”的原因。

### 2. 先手未同步到 worker（代码层，历史遗留）
- `js/core/ai.cjs` 原先把 `ai_init({ first: first_index })` 放在**显式先手覆盖之前**（`if (gl_cf_first !== 'rand') { ... first_index = ... }`）。
- 于是 worker 拿到的是随机先手，页面用的是玩家选的先手；两者不一致时回合方与血量互换。
- 实测：固定“我方先手·我方黑”连开 4 局，worker 的 `turnPlayer` 有 2 次为 1（白），worker HP `[6,5]` 与页面 `[5,6]` 相反。
- 后果：玩家落子被 `ai_turn` 按错误颜色写进 worker，`ZERO_THINK` 又按错误方思考，落点错乱/非法 → AI 看起来“不落子”。
- 修复：把 `ai_init` 移到先手与血量确定之后，并改为 `await`（非存档分支在 `state.turn_player = first_color;` 之后、`game_balance()` 之前；存档分支同样 `await`）。
- 复测：固定同一配置连开 4 局，worker `turnPlayer` 恒为 0、HP 恒为 `[5,6]`，与页面一致；简单/普通难度各连续多手均正常应手（`sims` 分别 55/115）。
- 注意：该缺陷在 `苦手文件/.../20260912` 备份中同样存在，属历史遗留，与本次取用弱化改动无关。

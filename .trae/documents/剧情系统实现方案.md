# 剧情系统实现方案

## Context（背景与目标）

需求：新增一个「剧情系统」，放在首页「文档相关」板块里。核心是**对话框（视觉小说式）＋ AI 对局**，并且对局中要能**定义刷草点**；整体是**关卡制**，管理员可新建/编辑/删除关卡；**暂时无需上线**。

现有可复用资产（已确认）：
- 残局挑战页 [challenge.html](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/4ascend-v2/html/endgame/challenge.html) 已经实现了「棋盘 Canvas + 4zero MCTS/战术 AI + ASCEND 结算动画」的完整对局闭环，剧情对局直接照搬其骨架。
- 残局关卡的后台管理模式 [levels.html](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/4ascend-v2/html/endgame/levels.html)（管理员校验 level==4、新建/编辑/删除、保存）可直接对标。
- 残局码编解码 [endgame.cjs](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/4ascend-v2/js/global/endgame.cjs)（`EndgameArchive.decode/encode`）与正着分支 `create_branch` 可复用，用来描述对局初始盘面与作者预设应手。
- 刷草引擎 [game_normal.cjs](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/4ascend-v2/js/global/fascend/game_normal.cjs) 的 `ed_pl_1()`（冷却/超载记账）与 `p_create()`（选点）是「可定义刷草点」的注入点。
- 文档服务的读写接口 `http_docs_query` / `http_docs_update`（[http.cjs](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/4ascend-v2/js/ref/http.cjs#L81-L147) 同风格的 `docs` 接口，`level=4` 才可写），已在线上可用。

**结论：不改后端、不新增 HTTP 接口、不部署。** 剧情目录整体作为一个 JSON 存进文档服务的 `story` 文档键；前端复用 `http_docs_query('story')` 读、`http_docs_update(token,'story',json)` 写。这样「放在文档相关里」同时满足「暂时无需上线」。

## 关键设计

### 1. 剧本格式（行式 DSL，贴近 PDF 原文，管理员易写）
剧本 = 纯文本，前端解析为节点流。语法：

```
# 注释
[导员ZERO] 你好~                      # 对话框：说话人 + 台词（支持 <玩家名称> 占位符）
? 选择是否观看新手教程                  # 选择节点
- 不观看 -> 结束                        # 选项 → 标签
- 观看 -> 教程开始
:教程开始                               # 标签定义
[导员ZERO] 好诶！让我们开始吧！
* 对局 第一场                          # 对局节点（后续缩进行为对局配置）
  残局码=<残局编辑器生成的残局码>        # 可复用现有残局编辑器产出初始盘面/HP/模式
  刷草点=4,4;5,4;6,5                    # ★ 可定义刷草点：有序消费，每次刷草事件落一株
  我方=黑                               # 黑/白
  先手=黑
  胜利=教程胜利
  失败=教程失败
:教程胜利
[导员ZERO] 干得漂亮！
结束                                    # 剧终
```

解析产出的节点类型：`say`（对话框）/ `choice`（选择）/ `game`（对局）/ `jump`（跳转）/ `end`。

### 2. 可定义刷草点（引擎层）
新增 [game_story.cjs](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/4ascend-v2/js/global/fascend/game_story.cjs)：`class GameStory extends GameNormal`，**只重写 `p_create(count)`**——
- 不再走自然选点（`p_scan_pos`/`p_scan_score`），改为从 `this.plant_points` 有序队列里取**1 个**点，返回对应棋盘 Pos；
- 队列耗尽则返回空（不再自然刷草，剧情对局刷草完全由作者定义）；
- `ed_pl_1()` 的冷却推进、超载判定、反升变蓄力等记账逻辑**全部沿用父类**（因为只换了 `p_create`），保证与规则引擎一致；
- 落地时沿用父类规则：空格→一草，已有一草的点→二草（作者可先在对局初始盘面预置一草来得到二草）。
- `natural_plant` 保持 `true`（否则 `ed_pl_1` 会提前 return，队列永远不消费）。

在 [build.cjs](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/4ascend-v2/js/global/fascend/build.cjs) 中 `require` 并挂到 `globalThis.FAscendExports.GameStory`，重编 `root/js/global/fascend.min.js`。

### 3. 剧情脚本引擎
新增 [story.cjs](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/4ascend-v2/js/global/story.cjs)，挂 `globalThis.StoryExports`：
- `StoryScript.parse(text)` → `{nodes, labels}`；`StoryScript.stringify(...)` 反向输出（供编辑器回填）；`StoryScript.validate(text)` 返回错误列表（标签缺失、对局坐标非法、残局码非法等）。
- `StoryRuntime`：播放状态机——`current()`、`advance()`（对话框/跳转）、`choose(i)`（选择）、`startGame()`（进入对局）、`finishGame(win)`（按胜利/失败/平局标签跳转）。
- `DEFAULT_CATALOG`：内置「新手引导」「进阶引导」两关剧本（内容取自 [story_raw.txt](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/tmp/story_raw.txt) 中两份 PDF 的提取文本），保证**离线/服务端为空时也能直接体验**。

### 4. 数据模型（存进 `story` 文档键的 JSON）
```
{ "version": 1,
  "levels": [ { "level": 1, "title": "新手引导", "script": "<DSL 文本>" }, ... ] }
```

### 5. 页面（放在 docs 目录）
- [story.html](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/4ascend-v2/html/docs/story.html)：关卡列表（对标 levels.html 的卡片/分页/进度）+ 管理员编辑器（关卡序号、标题、剧本 textarea、实时预览、保存/删除）。管理员判定：`http_user_info(token).level===4`；读写走 `http_docs_query/http_docs_update('story')`，失败时回退内置目录。
- [story-play.html](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/4ascend-v2/html/docs/story-play.html)：播放页（对标 challenge.html）。上半为棋盘 Canvas（`GameCanvas`/`Sound`），下半为对话框浮层（说话人头像/名字 + 台词 + 逐字显示 + 继续/选项按钮）。进入 `game` 节点时启用落子；AI 走子复用 worker 的 `ENDGAME_LOAD(snapshot)` / `ENDGAME_THINK(888)`（含斩杀/防自杀战术矫正）/`ENDGAME_APPLY`；每次刷草后调用 `ENDGAME_LOAD(RulesRuntime.snapshot(game))` 把新草同步给 AI；对局结束按配置跳转标签。
- [index.html](file:///d:/4ASECND%E5%A4%8D%E5%88%BB%E9%A1%B9%E7%9B%AE/4ascend-v2/html/index.html#L347-L361)：「文档相关」板块新增按钮「剧情系统」→ `/pages/docs/story.html`。

## 实施步骤
1. 新增 `game_story.cjs`，在 `build.cjs` 导出；先跑 `tmp/story-plants.test.cjs` 验证刷草队列行为。
2. 新增 `story.cjs`（解析/校验/状态机/内置目录）；跑 `tmp/story-script.test.cjs` 验证解析、标签跳转、选择分支、对局配置。
3. 写 `html/docs/story.html`（列表 + 管理员编辑器）。
4. 写 `html/docs/story-play.html`（对话框 + 对局）。
5. `html/index.html` 加「文档相关 → 剧情系统」入口。
6. 构建：`bun watch.cjs`（会重编 JS/HTML/CSS 到 `root/` 并执行 `rand.cjs` 版本号替换）。

## 验证方式
- 单元回归：`node tmp/story-plants.test.cjs`、`node tmp/story-script.test.cjs`（沿用 `tmp/` 下既有的 ESM→CJS 加载器写法）。
- 本地起服：`node server.cjs`（9001），浏览器打开
  `/pages/docs/story.html` 与 `/pages/docs/story-play.html`：
  - 对话框逐句推进、`?` 选项分叉、`->` 跳转、`结束` 收尾；
  - 进入对局后落子、AI 应手（含战术矫正状态提示）；
  - 到达刷草冷却时，草**只**出现在剧本定义的刷草点，且 AI 能看到新草；
  - 管理员（level 4）可见编辑器，可新建/编辑/删除并保存到 `story` 文档；非管理员看不到。
- 用浏览器子代理做一次端到端截图/交互核验。

## 约束与已知取舍
- 整个目录共享文档服务单键，受文档长度上限（64KB）约束；超出时需拆分为多个 key（后续再扩展）。
- 对局初始盘面复用「残局码」；作者预设应手（black_book/white_turns）仅在 `我方=黑` 时启用 `create_branch`，其余情况走自由 AI。
- 刷草点定义为「有序坐标队列，每次刷草落一株」；不提供按回合调度的时序表（后续可扩展）。

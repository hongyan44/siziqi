# 引擎侧增量（4ASCEND 自家 NNUE + 搜索）

这些文件来自 `/nnue-engine`，是"教师数据 → 自家引擎"这条链路的对应实现。
完整工程见 `/nnue-engine/fascend`（Rust 规则引擎 + PVS 搜索）与
`/nnue-engine/distill`（训练器、数据桥、标签生成）。

## features.rs —— 612 稀疏 + 113 稠密

| 区间 | 数量 | 含义 |
|---|---|---|
| 0..90 | 90 | 基础：6 类 × 15 轨道（黑/白/黑升/白升/草1/草2） |
| 90..270 | 180 | 棋型：2 色 × 6 类（活二/眠二/死二/活三/眠三/死三）× 15 轨道 |
| 270..390 | 120 | 潜力打：2 色 × 4 桶（m_a = 0 / 4 / 5-6 / ≥7）× 15 轨道 |
| 390..420 | 30 | 致命：该格该色 m_a ≥ 对方血量 |
| 420..432 | 12 | 攻防力量（hist(1..4) + 总力量档 + 打子数档 + 斩杀/被斩杀） |
| 432..612 | 180 | 链/其它 |

累加器 `ACC = 256`；头部 `369 (=256+113) → 32 → 1`，输出 `tanh`。

## search.rs —— depth-4 PVS + 确定性改造

* 迭代加深、PVS、TT、killer/history、可选的 LMR / qsearch
* `Searcher::reset_for_position()`：清空 TT、chance 采样计数、history/killers，
  让"同一局面 + 同一网络 + 同一深度"的搜索结果**逐位可复现**
* 这一条是标签侧的分水岭：不清理时同一局面在不同上下文里平均差 **0.27**（±1 尺度），
  网络只能学到噪声；清理后同一批数据的价值增益从 +15 Elo 提到 **+75 Elo**

## gen_labels.rs —— GTL-lite 标签生成

每一手只做一次 depth-4 搜索，然后：

* 根节点：`value = score / 4000`
* 主变第 k 层：`value = (-1)^k × 根值`（negamax 恒等式，**不需要再搜**）
* 开局随机手（5–12 子）也标（depth−1）
* 一次搜索产出 4.7 条标签（1200 局 → 72.7 万条）

## bridge.rs —— 教师 jsonl → 我们的训练集

重建 `Game`/`PotTable`，用与推理**同一个** `sparse_indices()` 生成特征，
并断言"引擎合法手集合 == 教师给的合法手数量"，防止状态编码有损。
